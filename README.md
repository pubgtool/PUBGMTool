# Line — голосовые звонки для Android

Нативное приложение на Kotlin, Android 8.0+, с чёрно-белым интерфейсом. Внутренний восьмизначный номер вместо SIM/телефона, голосовой WebRTC, выключение микрофона, динамик и код проверки соединения. Сервер Node.js передаёт только сигнальные сообщения, не записывает голос.

## Собрать и установить

Нужны Java 17, Node.js 24 и Android SDK. В Android Studio откройте корень проекта, установите SDK 36 и запустите `app`. На Linux без Android Studio:

```sh
bash scripts/setup.sh
./gradlew assembleDebug testDebugUnitTest lintDebug
npm test
# APK: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Скрипт устанавливает SDK в `.android-sdk` (или существующий `ANDROID_HOME`), принимает лицензии SDK и создаёт локальный `local.properties`. Java устанавливается обычным способом или через `mise use java@temurin-17`. Gradle Wrapper включён. Debug APK предназначен для проверки; для публикации нужна собственная release-подпись, не включайте ключи в Git.

## Созвониться

1. Разверните сервер с **HTTPS/WSS** и настройте TURN (ниже).
2. Установите APK на два телефона. В «Настройки» обоих приложений введите одинаковый адрес `wss://ваш-домен/signal`.
3. После подключения появится личный номер. Нажмите на номер, чтобы скопировать, и передайте другу.
4. Друг открывает приложение; наберите его восемь цифр и нажмите «Позвонить». Он нажимает «Ответить» и разрешает микрофон.
5. Во время звонка доступны микрофон, динамик и завершение. В уведомлении есть микрофон и завершение.

**Активный звонок** продолжает работать при нажатии Home/Back, удалении окна из списка последних приложений и однократном нажатии кнопки питания. Используются microphone foreground service, уведомление, аудиофокус и partial wake lock; экран не удерживается включённым. Принудительная остановка, выключение телефона, ограничения производителя, потеря интернета и остановка сервера могут прервать звонок. Невозможно честно обещать отсутствие любых лагов/обрывов. Голос без видео, адаптивный Opus/WebRTC и ограничение исходящего битрейта 32 Кбит/с снижают нагрузку.

**Входящие в этой версии доступны только при открытом приложении.** В фоне сохраняется уже начатый звонок, а не постоянное ожидание входящих. Push-вызовы при закрытом приложении требуют отдельной интеграции FCM/Android Telecom; здесь её нет. При переустановке/очистке данных выдаётся новый номер. Смена сервера также может менять номер.

## Сервер и TURN

```sh
npm --prefix server ci
# Секрет храните вне репозитория; тот же секрет у Coturn.
export TURN_URLS='turn:turn.example.org:3478?transport=udp,turns:turn.example.org:5349?transport=tcp'
export TURN_SECRET='REPLACE_WITH_A_RANDOM_SECRET'
# Только relay: не раскрывать сетевой адрес одному собеседнику другому.
export RELAY_ONLY=true
npm run dev
```

Сервер слушает `3000`; поставьте перед ним Caddy с шаблоном `deploy/Caddyfile`, заменив домен. Откройте 80/443 для Caddy, 3478 TCP/UDP, 5349 TCP и диапазон 49160–49200 UDP для Coturn. Внешний 3000 закройте firewall. Скопируйте и адаптируйте `deploy/coturn.conf.example`, используйте валидные TLS-сертификаты и лимиты трафика/квоты на TURN. Caddy не включает access log в шаблоне. TURN-конфигурация — шаблон, не протестированное production-развёртывание.

Без TURN звонки через некоторые NAT/мобильные сети не соединятся. `RELAY_ONLY=true` без TURN не позволяет серверу стартовать. TURN REST credentials ограничены по времени, обновляются при регистрации; для долгой сессии, превысившей их TTL, переподключитесь между звонками. Подробности и лимиты: [server/README.md](server/README.md). Один процесс сервера, локальный JSON `server/data/identities.json`, сохраните его для постоянных номеров. Для непрерывной работы настройте системный менеджер процессов и резервные копии защищённого файла.

## Приватность — без ложных гарантий

- Аудио шифруется **DTLS-SRTP между WebRTC-участниками**, в том числе при relay через TURN. Обычный TURN-сервер не расшифровывает голос.
- Сервер сигнализации — часть модели доверия: он видит номера, IP, SDP/ICE и время вызовов. Он их не журналирует, но оператор сети/сервера всё равно может наблюдать метаданные. Никакой гарантии «никто не отследит» нет.
- После соединения оба экрана показывают одинаковый 96-битный код, вычисленный из DTLS SHA-256 fingerprints. **Сверяйте его через другой доверенный канал** при каждом звонке. Несовпадение означает, что доверять соединению нельзя; завершите звонок. Код не сравнивается автоматически и не заменяет подтверждение личности. Один только замок/шифрование не защищает от подмены сигнализации доверенным сервером.
- По умолчанию сервер использует Google STUN, которому виден IP. Для большей приватности включите собственный TURN и `RELAY_ONLY=true`: STUN исключается, Android принудительно использует relay. TURN всё равно знает IP обоих участников.
- Нет аналитики, записи разговоров, контактов и доступа к телефонному номеру. Секрет установки хранится в приватном хранилище Android; backup/перенос данных отключены. Компрометация телефона, запись собеседником и глобальный анализ трафика вне защиты приложения.

## Проверки

`npm test`: регистрация/постоянство номера, авторизация, принятие и отклонение, busy/offline/self, тайм-ауты, disconnect и TURN. `./gradlew testDebugUnitTest lintDebug assembleDebug`: сборка, API/permissions и проверки адреса/кода безопасности.

Для сквозной проверки подключите Android-устройство/эмулятор через `adb` и запустите `bash scripts/test-device.sh` (также нужен `openssl`). Тест поднимает локальный TLS-сервер, создаёт второго настоящего WebRTC-участника, проверяет RTP-аудиопакеты и совпадение кода, микрофон, затем Home и выключение экрана. Временно сгенерированное доверие к сертификату действует **только для localhost и debug-сборки**; файлы удаляются после теста. Перед передачей APK заново выполните `./gradlew assembleDebug`, чтобы исключить тестовую конфигурацию. Тест не измеряет задержку/качество речи и не проверяет внешний TURN.

Для среды без аппаратного ускорения есть лёгкий AOSP-эмулятор Android 11: `bash scripts/start-test-emulator.sh`. На Android 14+ отдельно проверяйте ограничения foreground service на физических устройствах.

### Статус первой сборки

Сборка APK, Android Lint, два unit-теста Android и семь тестов сервера прошли. Сквозной RTC-тест **не подтверждён**: Android 15 в программном эмуляторе испытывал системные ANR, а среда дважды перезапускалась с потерей последних изменений при попытках проверки на AOSP. Стартовая ошибка Activity исправлена. Работа аудио, интерфейса и фонового звонка на физических телефонах, качество/задержка и внешний TURN пока не проверены. Это тестовая сборка, не production-релиз.

Полезные ограничения Android: [microphone foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone), [фоновые ограничения](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start). WebRTC Android SDK: [webrtc-sdk/android](https://github.com/webrtc-sdk/android).
